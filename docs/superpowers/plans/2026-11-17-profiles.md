# NBA Player & Team Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app that searches every NBA person and franchise and shows rich profiles. A person profile has a role timeline (player → coach), season stats, awards and a Wikipedia summary. A team profile has eras, season records, coaches and notable players.

**Architecture:** A one-shot, re-runnable importer pulls from `nba_api` (stats.nba.com), Wikidata and Wikipedia. Every raw response is cached on disk under `data/raw/`, so a re-import costs no network. It builds a SQLite database around **people + dated roles** and **franchises + eras**. People are indexed into the Elasticsearch already running for the HN project (index `nba-people`). FastAPI serves search and profiles to a React app.

**Tech Stack:** Python 3.12, uv, FastAPI, httpx, `nba_api`, SQLite (WAL), `elasticsearch[async]` 9.x against the existing `hn-es` container on :9200, Voyage `voyage-4` embeddings. Web: React, Vite, Tailwind, TanStack Query, react-router.

**Spec:** `docs/superpowers/specs/2026-11-17-nba-design.md` (scope update at the top: local only, no incremental sync, profiles first).

## Global Constraints

- Local only. No hosting, no nightly sync. `make import` rebuilds everything from the cache plus any missing fetches.
- **Verification is by real runs, not unit tests** (user preference: no unit tests). Each task ends with commands and their expected output.
- stats.nba.com: ≥0.6 s between requests, 30 s timeout, 3 retries with backoff, browser-like headers (`nba_api` defaults). It runs from the laptop.
- Wikimedia requests send `User-Agent: nba-profiles/0.1 (local research project)` and no personal email. Wikidata SPARQL: one query at a time.
- Never print or commit `VOYAGE_API_KEY`. It is read from `nba/.env`, which is git-ignored.
- Elasticsearch: reuse `localhost:9200` (container `hn-es`). Only create or delete `nba-*` indices; never touch `hn-*`.
- Every imported row keeps `source` (`nba` | `wikidata` | `wikipedia` | `derived`).
- Data paths: `data/nba.db`, `data/raw/`, `data/embcache.db`. All are git-ignored.

## Review Focus

1. **Diacritics and spelling.** "jokic" must find Nikola Jokić, "doncic" must find Luka Dončić. Pinned in Task 7.
2. **The same human in two NBA records.** A coach's `COACH_ID` may differ from their player `PERSON_ID`. JJ Redick must be one person with both roles. Pinned in Task 3.
3. **Traded players.** Season-total `TOT` rows must not double-count careers or create fake stints. Pinned in Task 4.
4. **People without a Wikipedia article or Wikidata link.** The profile still renders, with no wiki section and no error. Pinned in Task 9.
5. **Interrupted import** (network drop or rate limit midway). Re-running resumes from the cache with no duplicate rows. Pinned in Task 1 and Task 2.
6. **Ages at a point in time.** An age is computed on the event's date, not today's date, and a name is the one valid then. Kareem's 1971 title reads "Lew Alcindor, 24, Milwaukee Bucks". Pinned in Task 4.
7. **First-name-only and former-name searches.** "kobe" → Kobe Bryant, "lew alcindor" → Kareem, and the result says which name matched. Pinned in Task 7.

### Task 3: Import franchises, team seasons and coaching staffs

**Files:**
- Create: `backend/nba/ingest/nba_teams.py`, `backend/nba/ingest/link.py`

**Interfaces:**
- Consumes: `fetch.nba`, the `person` table from Task 2.
- Produces:
  - `import_teams(conn) -> dict[str, int]`, using these endpoints:
    - `FranchiseHistory` → `franchise` and `team_era` (city, nickname, from/to year, including defunct franchises);
    - `TeamYearByYearStats` per franchise → `team_season`;
    - `CommonTeamRoster` per team-season → the coaches → `role` rows (`head_coach` | `assistant_coach`, `source='nba'`).
  - `link.resolve_coach(conn, coach_id: int, name: str) -> int` returns a `person.id`. Rules, in order:
    1. `coach_id` equals an existing `nba_id`, and the normalized names are equal → that person.
    2. Exactly one person whose normalized full name matches → that person, `confidence=0.8`, logged in `person_link`.
    3. Otherwise create a new person (coach-only) with `confidence=1.0` (its own identity).
    4. If several people share the name → create a new person and add a `link_review` row listing the candidates.
  - `normalize_name(s) -> str`: NFKD, strip accents, lowercase, drop punctuation and the suffixes Jr/Sr/II/III.
  - `import_season_dates(conn)`: `LeagueGameLog` per season, for Regular Season and Playoffs (about 160 calls) → `season(season_id, start_date, regular_end_date, playoffs_end_date)`.

### Task 4: Derive player roles, stints and prominence

**Files:**
- Create: `backend/nba/derive.py`
- Modify: `cli.py` (`nba import derive`, and `nba show <name>`, which prints the timeline)

**Interfaces:**
- Consumes: `season_player`, `role`, `award`.
- Produces:
  - `derive_all(conn)`, which:
    - rebuilds the `player_stint` rows (one per person × team × season, excluding `TEAM_ID=0`/`TOT`);
    - rebuilds the `role` rows with `role_type='player'`, `source='derived'`: consecutive seasons with the same franchise merge into one role, so Redick has ORL 2006–13, MIL 2013, LAC 2013–17, PHI 2017–19, NOP 2019–21, DAL 2021;

  - `timeline(conn, person_id) -> list[dict]` returns the roles sorted by start. It is used by `nba show` and the API.

### Task 5: Wikidata enrichment (IDs, names, nicknames, owners)

- Create: `backend/nba/ingest/wikidata.py`

**Interfaces:**
- Consumes: `fetch.sparql`, `link.normalize_name`, `person`, `franchise`.
- Produces: `import_wikidata(conn) -> dict[str, int]`, which:
  1. Runs one SPARQL query for every item with the NBA.com player ID property. It returns qid, nba_id, label, `skos:altLabel@en`, nickname (P1449), birth name (P1477), enwiki sitelink and Basketball-Reference ID. The executor confirms the property IDs with a one-item test query first (Redick).
  2. Sets `person.wikidata_qid`, `wiki_title` and `bbref_id`.

  5. For franchises, maps team QIDs by the NBA team ID property if one exists, else by enwiki title, using a hand-written dict of the 30 current teams plus defunct franchise titles in `wikidata.py`. Imports owners (P127, "owned by", with start/end qualifiers) as `role_type='owner'`, `source='wikidata'`, creating people as needed.

### Task 7: Person search index (`nba-people`)

**Files:**
- Create: `backend/nba/search/{es,embed,people}.py`
- Modify: `cli.py` (`nba index`, `nba search "<q>"`)

**Interfaces:**
- Consumes: `person`, `person_name`, `role`, `wiki_passage` (summary).
- Produces:
  - Index `nba-people-v1` with alias `nba-people`, built by `es.rebuild(conn)` (create v-next, bulk, swap the alias, delete the old one).
  - Document fields:
    - `id`, `name` (display), `names` (all variants);
    - `roles` (keyword), `franchises` (keyword), `from_year`, `to_year`, `position`, `prominence`;
    - `profile` (text: position, teams with years, roles, awards, first 600 characters of the wiki summary);
    - `profile_vec` (dense_vector 1024, bbq_hnsw, from Voyage `voyage-4`, cached in `data/embcache.db`).
  - Analyzers:
    - `names`: standard tokenizer + lowercase + `asciifolding` (`preserve_original: false`);
    - `names.ngram` subfield: edge_ngram 2–15, search analyzer without ngram;
    - `profile` uses English stemming.
  - `search_people(q: str, role: str | None, franchise: str | None, k: int = 10) -> list[dict]`:
    - Name leg: a `bool` with `match_phrase_prefix` on `names` (boost 3), `match` on `names` with `fuzziness: AUTO` (boost 2), and `match` on `names.ngram`.
    - Wrapped in `function_score` with `field_value_factor(prominence, modifier=log1p, factor=1)`, `boost_mode: multiply`.
    - When the query has more than 2 words and the name leg's top score is low (no top hit whose `names` contains all query tokens), it also runs kNN on `profile_vec` and fuses with RRF (k=60), in app code as in HN.
